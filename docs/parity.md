# Behavioural decision record

Why govox behaves as it does. Each entry is a decision with its reasoning attached, and
several are traps that cost days to find — the kind of thing that looks like a redundant
line of code until you remove it.

**Read this before concluding a behaviour is a bug.** A surprising number of them are
load-bearing: an API that reports success and does nothing, a regex whose exact `\b`
semantics matter, an offset that must be counted in characters rather than bytes.

The marks — **ported**, **changed**, **dropped** — are historical. govox was rewritten in
Rust from an earlier, unpublished Python implementation by the same author, and this file
began as the ledger tracking that port: what was carried over deliberately, what was
altered, and what was left behind. The port is finished, so treat the marks as provenance.
The reasoning is the part that still matters.

Behaviour is now pinned by the golden corpora rather than by comparison with anything
external — see [index.md](index.md) and `crates/govox-core/tests/correction_golden.rs`.
When a decision here changes, update the entry in the same change.

Review it at the end of every milestone. An undocumented divergence found later is a bug;
a documented one is a decision.

|---|---|
| ported | Behaves the same. Divergence would be a bug. |

### Infrastructure

| Behaviour | Mark | Note |

| `sys.path` bridging to system PyGObject (3 call sites) | dropped | Existed only because uv-managed CPython cannot see apt's PyGObject. No equivalent problem in Rust. |
| Optional install extras (`audio`, `activation`, `recognition`, `vad`, `streaming`, `otel`, `accessibility`) | changed | Become cargo features. `govox doctor` must still *name* a capability that is not compiled in, so capability names live in `govox-core` and only implementations are gated. |

### CLI and config

| Behaviour | Mark | Note |
|---|---|---|
| Subcommands `run`/`doctor`/`devices`/`keys` | ported | Pinned by a test asserting the exact subcommand list. |
| `govox commands` | changed | An addition. The reference documents its grammar only in source, so a phrase could be understood and undiscoverable at the same time — macOS Voice Control answers "show me what to say" and govox had no equivalent. Every line is generated from the grammar tables, so the listing cannot drift from the behaviour, and each group reports whether it is switched on and which setting would enable it. Declared in `ADDED_SUBCOMMANDS` rather than folded into the guard test above, so that test keeps catching an *accidental* addition. |
| Exit codes: 1 runtime, 2 config | ported | `RestartPreventExitStatus=2` in the systemd unit depends on 2 meaning "do not restart". |
| `SuccessExitStatus=143` in the systemd unit | dropped | An artefact of `uv run` reporting its child's SIGTERM as an exit code. A real binary exits on SIGTERM normally. |
| Config layering order (default → XDG user → env → `--config`) | ported | Deep merge; non-table values, lists included, replace wholesale. Missing `--config` path is an error. |
| Resolved default configuration, every key and value | ported | **Verified by differential test**, not by hand-written assertions: `corpus/config-defaults.json` is compared field by field in `crates/govox-core/tests/config_golden.rs`. That test also contains a self-check proving it detects planted drift. |
| `GOVOX__A__B` env override with bool→int→float→str coercion | ported | Hand-rolled, **not** `figment` — the coercion order is a parity surface. One narrowing: Python's `int()`/`float()` accept digit separators (`1_0` → 10) and Rust's `parse` does not, so such a value arrives as a string and is rejected by the schema. Narrower, never wider. |
| `extra="forbid"` on the config root **only** | ported | The asymmetry is deliberate and was verified against the pinned source: an unknown *section* is rejected, an unknown *key inside a known section* is silently ignored. `deny_unknown_fields` is therefore on `Config` and on no section struct. Putting it everywhere — the obvious Rust instinct — would reject configs that work today. **Candidate improvement**, not to be made by accident: a typo'd key currently does nothing, silently. |
| Environment read from the process | changed | `Config::load_from` takes an injected `Environment`. `govox-py`'s tests use `monkeypatch.setenv`, which is order-dependent under any parallel runner; Rust's test harness is threaded by default, so the environment is a parameter. |
| `PersonalDictionary` TOML loading | ported | Including the `~/` expansion, which is load-bearing: the documented path is `~/.config/govox/dictionary.toml`, and without expansion the open fails and the daemon refuses to start. Same four validation errors. |
| Reload restricted to `[correction]` and `[logging]` | ported | Diffed through the serialized `toml::Table` rather than field by field. Hand-rolled comparisons are exactly where a new config key gets forgotten, and the failure is silent: the section stops being reported as changed and the user is told a restart is unnecessary when it is. A test asserts the section list has not drifted from `Config`. |
| `[feedback] app_rules` exempt from "restart required" | ported | Consulted per session, so they are already live. Reporting them would tell the user to restart when the rule had already taken effect — a false alarm that teaches them to ignore the message. |
| Personal dictionary load failure is fatal | ported | **Fixed a divergence introduced at M5**, where an unreadable dictionary only warned. It is text govox has been told to put in the user's documents: dictating without it is a silent wrong answer, not a missing feature. Unlike the optional layers (IBus, AT-SPI, tray), whose absence changes nothing about what gets typed. |
| Config and dictionary edits reload themselves | **new** | The daemon watches both files and reloads on save; the tray's Reload item stays, for the case where you want to be told what happened. Three things make it work rather than merely appear to: the *parent directory* is watched, not the file, because an editor's atomic save replaces the inode and a file-level inotify watch would survive exactly one save and then observe an unlinked inode forever; events are debounced by 300 ms, since one save is a burst and each event alone would recompile the correction pipeline; and a file that does not exist yet is still watched, because the day you first write `~/.config/govox/dictionary.toml` is the day the watch has to already be looking. Failure to establish the watch is logged and startup continues — a degraded daemon, not a broken one. |
| An automatic reload that changed nothing is silent | **new** | A *requested* reload always answers, including "nothing changed": a menu item that appears to do nothing is worse than a redundant notification. A *filesystem-triggered* one fires on every save, including a save that only moved a comment, so it reports only when something was applied, something needs a restart, or the file would not parse. Announcing no-ops would train the user to ignore the notification that tells them a restart is needed. |
| `--config` is carried into the reload | **fixed** | The path reached `Config::load` at startup and was then dropped, so a reload — and now the watch — silently re-read the *default* location instead of the file the run was started from. A daemon started with `--config` reloaded someone else's configuration, and reported success doing it. |
| Reloading the dictionary re-biases recognition | **fixed** | The dictionary is loaded in two places — the correction pipeline's replacements and whisper.cpp's initial prompt — and only the first was reloadable. A reload reported "dictionary" while recognition stayed biased by the *old* word list until a restart, which is the half that matters: the accuracy eval puts term recall at 20/27 with bias and 10/27 without. The prompt is now an `ArcSwap` read per decode rather than a `String` owned by the worker, so the swap needs no message on the audio queue and cannot wait behind a decode in flight. A decode already running keeps the prompt it started with. |

### Correction and editing

| Behaviour | Mark | Note |
|---|---|---|
| Whole correction pipeline, stage order included | ported | **238,780 corpus records at byte parity.** Generated by running the pinned govox-py over sweeps of its own lookup tables, not by hand-written vectors. |
| Editing: `compile_edit`, spans, phrase targeting | ported | Same corpus, covering every `EditAction` the grammar can produce against seven field states (no field, last-only, unicode last, matching field, mismatched field, no last, over-long field). |
| `replace X with Y` types Y as spoken, not folded | **deliberately-changed** | Both tier 2 slots came out of `normalize_command_text`, which lower-cases — so the replacement was typed into the document in lower case. "replace rentsync with RentSync" produced `rentsync`, making the command unable to do the thing it is most often reached for: fixing a name the recogniser got wrong. The slots are now taken from a case-*preserving* normalisation, and they part company deliberately. `phrase` is still folded, because it is a search key and `find_phrase` is `(?i)` regardless; `replacement` keeps its capitals, because it is text destined for the user's document. Punctuation stays stripped from both, which is not an oversight: `ensure_terminal_punctuation` may already have added a full stop to the utterance, so preserving punctuation would type "the new file**.**" — a sentence ending nobody spoke. The tier 2 patterns gained `(?i)` for the same reason the change was needed at all: `sentence_case` runs first, so the verb itself may arrive as "Replace". |
| The corpus agreed with the bug for 239,050 records | — | Worth recording, as the verbatim-field case above was. The fix moved **no existing record**: every `match_phrase_edit` input ever recorded was already folded, so nothing had ever asked what happens to a capital, and a full replay could not distinguish the defect from correct behaviour. The bless generator now emits cased inputs for every tier 2 verb, through both `match_phrase_edit` and `detect_command` at each side of the command-mode gate — 21 added records, nothing rewritten. Second time this exact shape of blind spot has been found: a sweep is only as wide as the argument combinations it was generated over, and case was a dimension the generator never varied. |
| `no space` is a mark whose mark is empty | changed | An addition from macOS's dictation vocabulary, implemented as a `SPOKEN_PUNCTUATION` row of `("no space", "", Attach::Tight)` rather than as a stage or a flag. `Tight` already means "close up on both sides", so an empty tight mark joins its neighbours — "camel no space case" → `camelcase` — with no new state and no new code path. It inherits the determiner suppression for free, which is what keeps "the no space rule" prose. The alternative considered and rejected was a suppression flag threaded through `separator_for`, which would have made spacing depend on daemon state that no pure function could then be tested against. |
| `space bar` is a command, not the text `" "` | changed | It joins `new line` and `new paragraph` in `COMMANDS`, so the injector presses the key rather than typing a character. That matters for the same reason the newline routing did: the clipboard injector would otherwise have to carry it, and pressing is the more reliable path. Cost is one keycode — `space` (57) — added to `KEYCODES`, and a mapping in each of the two injectors. |
| `numeral <n>` overrides the bare-small-number rule | changed | "Rule 2" keeps a lone number under 100 as a word unless a unit follows, because "I have one idea" is prose far more often than data. `numeral` is the escape hatch macOS offers for exactly that, and it only counts immediately before a number word — so "roman numeral" and a bare "numeral" stay ordinary words, and the fallback re-emits the word untouched. |
| `case_control` defaults on, and the config golden cannot see it | **deliberately-changed** | The setting was opt-in because "caps" is an ordinary word and a marker firing inside prose eats the word after it. The risk is unchanged; the judgement is that having no way to say "capital" while dictating a name or an acronym costs more, daily, than the rare misfire. Worth recording separately: `correction.case_control` is on `config_golden`'s `RUST_ONLY_KEYS` allowlist, which is *stripped before the snapshot is written*, so `corpus/config-defaults.json` never carried this default and blessing it produced no diff at all. A corpus that documents "every config key" does not, and the allowlist is where the exceptions are. Pinned now by a unit test covering both the shipped `default.toml` and a user file that edits `[correction]` without naming the key. |
| `press <key>` over a vetted key table | changed | An addition, taken from macOS Voice Control's `Press <key>`; the reference had no equivalent. The table is the security boundary, not a convenience: `ydotool key` accepts an unparseable name, exits 0 and presses nothing (see the `KeyCode` entry above), so a grammar that forwarded spoken words would be a silent no-op generator. `PRESS_KEYS` maps each spoken spelling to a chord name that `keycodes::KEYCODES` carries, and a test walks the whole table through `parse_chord`, so an unreachable key is a build failure rather than a dead command. Being table-constrained is also what makes a bare verb safe in **tier 1**: "press the button" matches nothing and dictates as text, so the command needs no command-mode gate. Keys `KEYCODES` does not carry — function keys, space, most letters, every modifier combination — are omitted rather than guessed, because a keycode that cannot be verified on this hardware is exactly how a silent no-op ships. |
| `PressKey` carries its key in `phrase` | changed | Not a new slot on `EditAction`. The golden corpus records an edit as a fixed object, so adding a field would rewrite every one of the ~7k edit records with a `null` and bury the change under its own diff. `phrase` is already an optional free-form string, the grammar only ever fills it from `PRESS_KEYS`, and the corpus took **120 added records and zero rewrites** as a result. The cost is that `phrase` now means "the target, whatever kind of target this op takes"; the compiler cannot enforce that, so the guard is the grammar being the only producer. |
| Contraction spellings are listed, not derived | changed | `let's type` / `let's command` and their variants are three table entries each, not one. `normalize_command_text` replaces a non-word character with a **space** rather than deleting it, so "let's" becomes `let s` — a two-token form that no single spelling covers. Listing `lets`, `let s` and `let` is the cheap answer; teaching the normaliser to elide apostrophes inside words is the expensive one, and it would change how every other stage sees every contracted word in the corpus. Which spelling the recogniser emits is not under our control, so a phrase matching only the punctuated form would work intermittently — the worst failure mode for a command whose whole job is to get you out of a mode. |
| Short aliases for leaving command mode | changed | An addition: `dictate`, `text mode`, `type mode`. Only the leaving side gained them, because that is the phrase said to get back to writing. The constraint that picked the words is that `MODE_COMMANDS` is looked up **regardless of which mode is current** — a mode phrase is therefore removed from the language of ordinary dictation the moment it is added, so "done" and "stop" were rejected as things one plausibly says alone. Nothing is dormant: with `[editing] command_mode = false` the lookup is skipped and every alias dictates as text, which the corpus now pins at both settings of that switch for every mode phrase, new and old. |
| `kill` as a second spelling of the `delete` verb | changed | An addition, and a table entry rather than a rule change — `last` was already a direction word, so `kill last word` parses on the existing `<verb> <direction> [count] <unit>` pattern with no new regex. The reason is length, not meaning: deleting the previous word is the most frequent edit there is, and "delete previous word" is six syllables to "kill last word"'s three. Both spellings stay; neither costs anything, and people reach for different words under frustration. Safe as a bare verb because tier 1 requires a direction *and* a unit, so "kill the process" matches nothing — and `kill` is deliberately **not** added to the tier 2 phrase patterns, which take `delete <phrase>` and `select <phrase>`. Tier 1 runs whether or not command mode is on, so a verb that could take a free-form target there would be able to swallow an ordinary sentence. All 239,050 corpus records replayed **unchanged**, which is the evidence that this is additive: no recorded input reaches the new alternative. Pinned going forward by four tests in `grammar.rs` — parity with `delete`, and the negative cases. |
| `collapse_repeated_words` backreference `\b(\w+)(\s+\1\b)+` | ported | Via `fancy-regex`, pattern character-identical. Not hand-rolled: `\b` means `"the, the"` is *not* collapsed, and reproducing that by hand invites exactly the divergence the corpus exists to catch. |
| Punctuation paired-prefix negative lookahead | ported | Via `fancy-regex`. |
| Code-point (not byte) offset arithmetic | ported | Spans and the editor work in character offsets throughout; `byte_to_char` converts at every regex boundary. A byte offset would emit the wrong keystroke count into the user's document on any non-ASCII text. |
| Multi-code-point emoji counted as >1 by `len()` | ported | Python counts `❤️` as 2 code points and emits 2 backspaces; the port does the same, including where it is arguably wrong. Covered by the `last-unicode` corpus model. |
| Spoken-emoji table contents | changed | Three phrases added beyond `correction/emoji.py`: "sad face" → 🙁 (the same character as the ported "frowning face", because people say either and mean one), and "kissing face" / "kiss face" → 😘. 😘 is *face blowing a kiss* rather than the literal 😗 *kissing face*, on the grounds that it is what someone dictating the phrase means. All three keep the module's two-word rule and the determiner guard, so "a sad face" is still left alone. The corpus is generated by running govox-py and therefore cannot cover additions; they are pinned by unit tests in `emoji.rs` instead. Verified absent from all 238,780 corpus records before adding, so parity is unaffected. |
| `re.escape` output | ported | Python (3.7+) escapes ASCII whitespace and a few harmless punctuation marks that Rust's `regex::escape` leaves alone. Functionally identical, but `bounded_pattern` returns the pattern *string*, so `py_escape` reproduces the reference byte for byte rather than leaving a difference to reason about later. |
| Dictionary regex compilation | changed | `CompiledDictionary` builds the patterns once. The reference compiles per call, but Python's `re` has an internal pattern cache that hides the cost; Rust has none, so a literal port recompiles every replacement on every utterance. |
| Spoken symbol names | changed | 21 phrases added beyond the reference's punctuation table — `at sign`, `dot`, `slash`, `forward slash`, `backslash`, `underscore`, `ampersand`, `asterisk`, `tilde`, `hashtag`, the brace pair, and the `<x> sign` forms. Without them an email address or a path could not be dictated at all, which macOS Dictation has always handled. Every entry is either suffixed "sign" or is a word with no other everyday use; `at`, `plus`, `equals`, `less than`, `star` and `pound` are **not** accepted bare, because each is an ordinary sentence waiting to happen. |
| Bare `dot` as a mark | changed | The one symbol entry that breaks the module's own rule about everyday English, and it is argued rather than assumed: "dot com" is simply how an address is said, and without it the address case the section exists for still does not work. Its false-positive cost ("using dot product") is real but strictly smaller than that of `period`, which has shipped from the beginning — "the Victorian period" is a likelier sentence than any bare "dot". The determiner guard covers "a dot" and "the dot", and `\b` means the plural "dots" never matches. |
| `Attach::Spaced` | changed | A fourth attachment, needed because spoken symbols divide into two shapes and no existing variant produced the second. A symbol inside an identifier closes up (`Tight`) — "rocky at sign gmail" is one token. A symbol standing in for a word is spaced like the word it replaces: "Tom ampersand Jerry" → "Tom & Jerry". |
| Spoken case control | changed | An addition with no counterpart in the reference, modelled on macOS Dictation: `all caps <word>`, `caps <word>`, `no caps <word>`, each with an `on`/`off` span form. Runs **last** in `apply_rules`, after `sentence_case` and `capitalize_after_terminators`, because both only ever *add* capitals — a "no caps" applied before them would be undone at exactly the sentence start where it was most likely meant. Off by default (`[correction] case_control`): "caps" is an ordinary English word, and a marker that fires inside prose does not merely fail, it eats the word after it. |
| Activation keys accept a list; default is double-tap either Control | changed | The default was `mode = "toggle"` on `KEY_SCROLLLOCK` — a key most keyboards no longer have in a reachable place. It is now `mode = "double_tap"` on `["KEY_LEFTCTRL", "KEY_RIGHTCTRL"]`, following macOS Dictation, which is the UX reference wherever parity does not bind. **The mode and the key are one decision, not two.** Control is pressed constantly, so `toggle` on it would start dictation on every copy; double-tap is what makes an everyday key safe to bind, and binding an everyday key is what makes the shortcut reachable. Any activation key now takes either a name or a list of them, and the listed keys share one double-tap timer — left-then-right Control is a double tap, because the two Controls are one key to the person pressing them. |
| A chord cancels a pending double tap | changed | Required by the above, and a real defect before it: `handle_double_tap` counted any two presses of the key inside the window, so **`Ctrl+C` twice in a terminal started dictation** — two Control presses with a `C` between them. That is how a running command is interrupted, so the commonest keystroke in a shell would have toggled dictation. An ordinary key pressed after a tap now cancels it, making the press a chord rather than a tap; modifiers do not cancel, so `Ctrl+Shift` stays a chord in progress. The module's own comment already claimed "Right Ctrl as part of a real shortcut is ignored" — it was true only of a *single* press. |
| Blessing the config snapshot preserves the declared additions | changed | `bless_the_config_golden` wrote the whole Rust schema, which includes the `RUST_ONLY_KEYS` allowlist, so any bless folded those keys into the snapshot and left `every_declared_addition_is_really_an_addition` failing on the next run — the allowlist and the snapshot describing different files. Bless now strips them back out, and panics if an allowlisted key is not in the schema at all. |
| Verbatim fields split into *single-token* and *spaced-words* | changed | Standing prose rules down and running utterances together were one decision, and that conflated two questions. Dictating twice into a terminal produced `…it does now.this is fun!`: `apply_rules` returned from the verbatim arm before the separator was ever considered. `FieldRules` now answers both separately — `TERMINAL` is `SpacedWords` (no capitals, no closing full stop, but a separating space), every other verbatim purpose is `SingleToken` (no space, so `example` then `dot com` still joins as `example.com`). One enum rather than two booleans, because the fourth combination — prose rules with no separator — describes no field that exists. The cost is the mirror image and is accepted: dictating a hostname across two utterances *inside a terminal* now gives `example .com`. That needs a hostname split mid-word at a shell prompt; running every multi-utterance command line together was the commoner failure by a wide margin. |
| The corpus could not have caught it | — | Worth recording, because the safety net not catching this is the more useful finding. All 238,973 records replayed **unchanged** through the fix: the corpus paired a verbatim purpose only ever with an empty caret, so nothing had ever asked what a second utterance does against existing text. The bless generator now emits that matrix directly (rules × text × caret), which is why the case is pinned going forward. A corpus sweep is only as wide as the argument combinations it was generated over. |
| Case-control spans end with the utterance | changed | A span opened with "all caps on" closes when the speaker stops, whether or not "all caps off" was said. Carrying the mode across utterances would mean a daemon-level flag outliving the sentence that set it, and a user who forgets to close it typing in capitals until they work out why — the trap `[editing] command_mode` is opt-in to avoid. macOS keeps the mode live; this is a deliberate divergence toward the safer failure. |

### Desktop integration

| Behaviour | Mark | Note |
|---|---|---|
| `ydotool key` given raw keycodes only, never names | ported | M3. A name exits 0 and presses nothing. `KeyCode` has no public constructor and `KeyEvent` renders only as `<code>:<pressed>`, so no argv can carry a name; the negative test sweeps every action and every table name anyway, as executable documentation. |
| 25-key keycode table, modifier press/release ordering | ported | Modifier order follows the chord as written and releases in reverse, so `"shift+ctrl+a"` is a different argv from `"ctrl+shift+a"`. Pinned by test. |
| `ydotool type` splitting on `\n` and pressing Enter | ported | Whether `ydotool type` turns a `\n` into a keypress is not assumed — the same silent-no-op class of bug. Empty segments are skipped. |
| Clipboard `wl-copy` + Ctrl+V, and the fallback selector | ported | The fallback clipboard is built with `paste_after_copy = false`: pasting needs `ydotool`, and we only reach the fallback because `ydotool` just failed. |
| Emoji routed to the clipboard and pasted | changed | `ydotool` types by emulating keycodes and no keycode produces an emoji, so `ydotool type 👍` exits 0 and types nothing — another "silent success", and the reason `[correction] spoken_emoji` appeared to do nothing when switched on. It is deliberately *not* given a number: the numbered family below is the IBus one, and this is the injection path. Text containing a pictographic character now goes to the clipboard and is pasted. This is a **router, not a fallback**: the decision is made from the text before anything is attempted, because the failure it avoids is not one `ydotool` reports. Pasting is safe on this path precisely because `ydotool` is available, which is what separates it from the fallback above. |
| Scoring normalisation for the accuracy eval | changed | An addition with no counterpart in the reference. Case and *trailing* punctuation are stripped before scoring, because both are added by the correction pipeline or vary by decoder, and counting them would measure `ensure_terminal_punctuation` rather than the recogniser. **Interior punctuation is kept**, which is the whole point: `rentals.ca` must not score equal to `rentals ca`, since turning the second into the first is exactly what a dictionary rule does. Word error rate is deliberately **not clamped** at 1.0 — a rate above it means more wrong words than there were words to get right, usually a hallucination, and flattening that would hide the case most worth seeing. See `docs/guides/accuracy-eval.md`. |
| The emoji router asks whether a clipboard exists | changed | The router above routed pictographic text to the clipboard *unconditionally*, and `FallbackInjector` fell back to it on rejection, on machines where `wl-copy` is not installed — so one emoji failed the whole utterance rather than degrading. `capabilities()` had always computed the answer; `select_injector` simply never consulted it. It now does, and a ydotool-only session drops what it cannot type, renormalises the spacing the removal leaves behind (`"Thanks 🙂."` → `"Thanks."`, not `"Thanks ."`), types the rest, and **notifies every time** — each utterance loses different characters, and a silent partial insertion is the failure this project exists to refuse. An utterance that is nothing but emoji types nothing and records no backend, rather than shelling out with an empty string. |
| A session with no injection backend says so | changed | With neither `ydotool` nor `wl-copy`, `select_injector` recorded `Clipboard` up front — so the About menu named a working backend for a machine that cannot type a character, and `Capabilities::supported` (which computes exactly this) is consulted nowhere in the daemon. The report now stays `NotYet`, the row reads `nothing available (no ydotool, no wl-copy)`, and startup logs an error. govox still runs: recognition, the corpus and the HUD are all worth having while injection is being fixed, and refusing to start would remove the diagnostic that explains why. |
| What counts as untypeable | changed | Pictographic ranges only (`U+2600–27BF`, `U+2B00–2BFF`, `U+1F000–1FAFF`, plus `U+FE0F` and `U+200D`), deliberately **not** "non-ASCII". Accented and non-Latin text is alphabetic, is typed today, and keeps the same path — rerouting every non-English utterance through the clipboard would be a far larger change than the bug being fixed. The two non-ASCII marks govox itself produces, `—` (U+2014) and `…` (U+2026), sit below every listed range. |
| Unknown `CommandAction` name | ported | A no-op, not an error, matching the reference: the correction pipeline is the only source of these names. |
| Fallback on a *non*-rejection error | changed | `govox-py` catches only `InjectionRejected`, which is the only error its injectors raise. The Rust `Injector` returns a `GovoxError` that could be any variant, so the fallback matches `InjectionRejected` explicitly and propagates the rest rather than papering over an unrelated failure. |

### Audio, VAD and activation

| Behaviour | Mark | Note |
|---|---|---|
| `VadSegmenter` hysteresis, hangover and minimum-length drop | ported | Pure state machine over a supplied probability, so it is tested with no model and no microphone. |

| Recognising which words a hypothesis already committed | **deliberately-changed** | The reference drops every word starting before `last_committed_time - 0.1`, then de-duplicates a repeat of up to five words at the join. Both halves fail here, and they fail by **losing words out of the middle of a sentence** — the streaming path scored twice the utterance path's word error rate until this was found. whisper.cpp's DTW timestamps are not stable between decodes of overlapping windows: traced on `prose-groceries`, "the" came back at 1.28–1.57 s in one decode and 0.80–0.99 s in the next, so a 0.1 s slack discarded it as already-committed when it had never been committed at all — and once discarded it can never be re-offered, though its audio is still in the window. The five-word cap fails independently, as soon as a sixth word is committed while the window still holds it. The overlap is now found by **matching text against the committed tail** — at most `MAX_TAIL_MATCH` (8) words of it, with its **position in the hypothesis searched for rather than assumed**, longest match first, with the timestamps demoted to a sanity check at the join and to breaking ties when a tail matches in more than one place (`JOIN_DRIFT_S`, 2.0 s — 1.22 s of drift was observed on `twillingate-drive`) so that a word genuinely said twice after a pause is still not mistaken for a repeat. Matching ignores case and edge punctuation, because the model supplies both from context and the context changes as the window grows: "milk." at the end of one hypothesis is "Milk" mid-sentence in the next, and treating those as different words typed it twice. The timestamp filter survives only as a fallback for when no text overlap exists at all. Matching the whole committed region from its first word was tried first and is not enough: one revised word behind the commit point breaks the alignment, the fallback then lets the committed tail through, and it is typed twice — a long session produced "but the the pipeline runs runs in GitLab". Only the tail is matched now, so what the model does behind it no longer matters. Measured on the corpus at a pinned cadence: raw WER 0.227 → 0.146, corrected 0.200 → 0.115, term recall 19/27 → 22/27, no duplicated words on any clip. |
| Where the audio buffer is cut when trimming | **deliberately-changed** | The reference cuts flush at the end of the last committed word, and so did this: everything before it is settled, so the decoder never needs it again. But the words *after* it are **not** settled, and they are re-decoded from whatever audio is left. Cut flush and the uncommitted tail gets no run-up at all — traced on a long session, "runs in GitLab" was correct in the window before the trim and came back from the 1.1 s fragment left afterwards as "In GitHub.", then never recovered, because nothing re-offers a word once its context is gone. The cut is now held `TRIM_CONTEXT_S` (2.0 s) behind the commit point. That margin is a preference, not a guarantee: it yields to a backstop that keeps the buffer inside its limit, because a margin comparable to `buffer_trimming_sec` would reclaim nothing per trim and let the window grow for the length of the session — the pathology in the row above. It also never cuts past the commit point. Caught by an existing test (`word_times_stay_in_session_time_across_a_trim`, whose 1.5 s limit is smaller than the margin), which is why the backstop is there. Long-session word error against a one-pass decode of the same audio: 0.081 → 0.032. No measurable decode cost — the same 48 decodes over a 24 s session. |
| `np.append` audio buffer | changed | A `VecDeque` ring. The reference copies the whole buffer on every chunk — O(n) per 500 ms for the length of the session. |
| Word timestamps from a word list | changed | faster-whisper returns `word.start/end`; whisper.cpp has no word-timestamp flag, so the idiom is `token_timestamps` + `max_len(1)` + `split_on_word`, which emits one *segment* per word. Spans come off segments instead. |
| `[streaming] buffer_trimming = "sentence"` | **dropped** | Needs a sentence tokenizer for the target language — a dependency for a bounded gain over trimming at a committed word boundary, which is what both modes now do. Logged at debug when configured, so it is visible rather than silent. `segment` is the default and the recommended value upstream. |
| Streaming session wiring in the daemon | ported | Capture routes through `OnlineProcessor` while a streaming session is live, and the hypothesis goes to the preedit sink and the caption together. `[streaming] enabled` is `false` by default. |
| Trimming the audio buffer with nothing committed | **deliberately-changed** | The reference only ever trims at a committed word, so a window that commits nothing is never trimmed. That is not a safe idle state: whisper.cpp answers a chunk it cannot place with no words at all (`single timestamp ending - skip entire chunk`) and re-decodes the whole window each time, so the buffer grows for as long as the user speaks and every decode costs more than the last. Observed in the field as a session that never ended and a daemon that stopped servicing its own stop key. `forced_trim_point` now cuts blind to the configured limit, discarding audio that produced nothing, and warns when it does. |
| Decode pacing | **added** | No equivalent in the reference. The streaming decode is awaited on the event loop, so consecutive decodes each slower than the audio they consume starve every other event — including the key that ends the session. A decode is skipped unless at least as long has passed as the previous one took, holding the duty cycle near half. Costs a little hypothesis latency; buys a daemon that always answers its hotkey. |
| Reusing one `WhisperState` across decodes | **deliberately-changed** | The reference creates a state per decode, and so did this until now; at a 0.25 s chunk size that allocates the KV caches and the backend scheduler several times a second. One state held on the worker thread cuts a streaming decode from 0.240 s to 0.215 s, measured at a pinned cadence so both runs decode identical windows. It is **not** behaviour-neutral, which is why this is a change rather than an optimisation: with the same windows and the same model, 6 of 29 clips decode to different text. On this corpus that is a small net gain (raw WER 0.242 → 0.227, corrected 0.229 → 0.200, term recall 20/27 → 19/27) and it repeats exactly run to run, but decode output now depends on decode history. `prompt_past` is cleared per call under `no_context` and the sampling RNG is reseeded per call, so the mechanism is neither of those and is not yet identified. Freeing that state at shutdown segfaults inside the Vulkan driver — `WhisperRecognizer::drop` deliberately does not join the worker thread, so the free races process exit — so the worker leaks the model on its way out, which is what exiting was doing anyway. |
| Scaling `audio_ctx` to the streaming window | **dropped** | Whisper encodes a full 30 s mel window however little audio it is given, so a 3 s streaming window looks like it is paying ten times over. Measured, it is not: on a Vulkan build, scaling the encoder context to the real window produced **no speedup at all** (0.213 s against 0.215 s) — the encoder is not where a decode's time goes — while term recall fell 19/27 → 13/27. It is also unsafe on this path. Word timestamps need DTW, DTW's median filter is hardcoded to width 7, and a truncated context makes the decoder emit garbage on a near-empty span, tripping `WHISPER_ASSERT(filter_width < a->ne[2])` at `whisper.cpp:8772`. That is `abort()`, not an error return: nothing in Rust can catch it, and in the daemon it lands mid-sentence. |
| `temperature_inc` left at whisper.cpp's default | ported | Worth recording because turning it off looks free and is not. whisper.cpp re-decodes at rising temperature when a pass trips `logprob_thold` or `entropy_thold`, which was the leading explanation for "sometimes the caption takes too long". Setting it to 0.0 bounds that tail for about 5% of a decode and costs raw WER 0.247 → 0.283 and term recall 20/27 → 16/27. The fallback earns its cost. |
| `n_threads` left at whisper.cpp's default | ported | `min(4, cores)` on a 16-core machine looks like an oversight. Measured on a Vulkan build it is not: 8 threads decode in 0.235 s against the default's 0.235 s, and 16 threads are slower at 0.243 s. The decode is GPU-bound and extra host threads only contend. A CPU build would answer differently. |
| Session start and stop mapping the overlay | ported | `show` on the session edge, `hide` on the closing edge, both between the chime and the tray pulse exactly as `_start_layers`/`_stop_layers` order them. Missing in the first cut of the fan-out, which sent captions to a helper it had never told to map its window — so the HUD received a whole session's text and stayed invisible. Now pinned by a test against a recording sink. |
| Ending the session relative to the commit | **deliberately-changed** | The reference tears the session down on the key release. Here recognition and injection run on their own task, so doing that clears the preedit before the commit reaches it — the commit then finds no live input method and falls back to typing the text a keystroke at a time, which is visibly slow and is the one thing preedit exists to avoid. Teardown is now a job queued behind the work it ends, with an inline fallback if the queue is full. |
| Silence auto-stop going down the stop path | **fixed** | It flushed the segmenter and nothing else, so a streaming session kept running and the input method stayed activated — an automatic stop was not, in fact, indistinguishable from a manual one, which is what its own doc comment promises. Both now call `stop_session`. |
| Decoding a window with no speech in it | **deliberately-changed** | No equivalent in the reference, which decodes whatever it has. Asked to transcribe silence, whisper.cpp does not answer "nothing" — it answers with what its training data put after silence, reliably `www.github.com` or `Thank you for watching!`. Every session begins with silence, because it starts on a keypress and speech follows a moment later, so this fired every time: a URL appeared under the caret before the user had said a word. The decode now waits for the VAD to report speech at least once, **and** the silence buffered before that moment is dropped, keeping a 300 ms pre-roll. Gating alone was not enough: at the instant speech is first detected the buffer holds a second of room tone and one frame of voice, so the first decode still saw a window that was almost entirely silence and still filled it. The pre-roll covers Silero's onset latency so the first consonant survives. Neither was sufficient either: `min_chunk_size_s` bounds the *window*, not the speech in it, so at 0.5 s the first decode still ran on a 0.3 s pre-roll plus 0.2 s of voice. The gate is now on voiced audio heard (`MIN_VOICED_S`), independent of buffer length. Measured at 0.3 s: transcription is 44 ms on this hardware, so the gate — not the model — is what the user waits through before their first word appears, and it is no longer the only defence. `is_silence_artifact` withholds a stock phrase that slips through and LocalAgreement will not commit what a second decode does not confirm. |
| Decoding the audio left over at the end of a session | **fixed** | `finish` returned the standing hypothesis and cleared the buffer, so the up-to-`min_chunk_size_s` of audio the model had never seen was discarded — a session truncating its own last word. It now runs a final decode, which is also what transcribes a session too short to have tripped the voiced gate — but only when the VAD saw at least `TAIL_MIN_VOICED_S` of speech since the last decode. A session ends a moment after the last word, so the leftover is usually the silence between finishing speaking and reaching for the key, and decoding that appended the stock phrase to the end of the user's sentence. The tail is passed through `is_silence_artifact` as well: unlike a provisional hypothesis, a tail is committed to the document. |
| Overlay following the caret | ported | `expect-anchor` at session start, then `anchor`/`compact` alongside each hypothesis, both deduplicated — an unmoved caret would otherwise mean a write down the helper's pipe on every update. Driven from the hypothesis rather than the reference's timer: the caret only moves as text is inserted, so the two already happen together. `overlay_require_caret_width` withholds the *position* of an untrustworthy rectangle without changing `compact`, which answers a different question — whether the field is showing the dictation — and must stay true for a client like Chrome that reports a useless caret but does render the preedit. |
| `[[feedback.app_rules]]` matching | ported | The rule is resolved once per session against the focused window's label and applied to the reported caret. The label is `"Application / Title"` — confirmed live as `ptyxis / personal | ◐ port-govox-py-to-rust — zellij` — and `match` is a case-insensitive substring of it, so `"google chrome"` matches whatever page is open. `AtspiTextModel::active_window` had produced this all along for the diagnostics; the `TextModel` method was left on its `None` default and never delegated to it, so the rules could not match anything while the label they needed was being computed a few lines away. Logged at debug with the label whether or not a rule matched: a line only on success cannot distinguish an unnamed window from a name the rules do not cover. |
| Wildcards in `match` | **added** | Not in the reference, which only ever substring-matches. A pattern containing `*` or `?` is matched as a glob against the *whole* label, so a rule can say "this application, but only this document" — something a substring test cannot express, since it can only widen. Patterns without a wildcard keep the substring behaviour, so existing configs are unaffected. Matched over `char`s, because window titles carry whatever the application put in them. No escape syntax. |
| Showing the first hypothesis of a session | **deliberately-changed** | The reference shows provisional text from the first decode. Here a session's opening words are withheld *only when they match Whisper's answers to silence* (`is_silence_artifact`: bare domains, and a handful of stock sign-offs), because the agreement check that would discard them runs a decode after they have already been shown. Withholding every first hypothesis was tried and reverted: stacked behind the voiced gate, a decode and the pacing pause, it put the first visible text seconds after the user began, and an utterance ending before the second decode showed no provisional text at all. |
| Spawning the overlay helper | **deliberately-changed** | The reference spawns on the first command. Here it is started at daemon startup: a process launch, an X11 connection and a fontconfig lookup between the keypress and the card is a delay visible on the first session after every restart, which is exactly when someone is watching for it. Costs an idle process. |
| When the anchor is sent | **deliberately-changed** | Alongside the audio frames rather than only with each hypothesis. The caret is state the input method pushed to us, so reading it is a lock and a comparison, not a round trip, and it is deduplicated — but the client reports its caret within milliseconds of the session opening, and waiting for the first recognised words put the card in its corner for a second or more first. |
| Driving the level meter | **fixed** | The pipeline computed the smoothed microphone level and discarded it (`let _meter = ...`), so `Level` never reached the helper, `has_level_feed` stayed false, and the card rendered completely static for a whole session — a listening overlay indistinguishable from a frozen one. It is the only element that moves while the user speaks. Now sent per frame and pinned by a test against a recording sink. |
| Click-to-stop | ported | `watch_stops` was implemented and tested and nothing called it, so the flag reached the helper and the click reached nobody. The helper's `stop` now arrives as an event — the read happens on its stdout thread and activation state belongs to the loop — and runs the same `auto_stop` the silence timer does, so a click is indistinguishable from a timeout. Push-to-talk is exempt exactly as the reference documents: there is no latched session to flip off, and withholding the flag is what keeps the card click-through, since the helper only claims an X11 input region when told click-to-stop is on. `try_send` rather than blocking: a full queue means the loop is already behind, and the user will click again long before a blocked thread helps. |
